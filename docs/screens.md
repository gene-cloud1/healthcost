# 화면 목록

기존 플로우 + 권장 플로우(위치 자동매핑, 보건소 필터, 병원 상세) 기준. 이 서비스는
"화면 복잡도 최소화"가 PRD 원칙이라 화면 수를 늘리지 않는 쪽으로 판단했고,
위치 자동매핑·보건소 필터는 별도 화면이 아니라 메인 화면 내부 강화로 처리했다.

| 화면 이름 | 사용자가 하는 일 | 부르는 엔드포인트 | 빈 상태 | 에러 상태 |
|---|---|---|---|---|
| 검색·비교 메인 화면 (기존, 강화 대상) | 항목 검색 → 지역 선택(또는 GPS 자동매핑) → 정렬 → 병원/보건소 결과 비교 → 카드 인라인 상세보기(주소/카카오맵/네이버맵/홈페이지 링크) | `GET /search/catalog.json`, `GET /search/districts/{hash}.json` (+ 브라우저 Geolocation API, 위치 자동매핑용 시군구 대표좌표는 신규 정적 파일 필요 — 예: `GET /search/district-centroids.json`) | "아직 '{item}' · {district} 조합의 실제 데이터가 없어요" (이미 구현됨, `App.tsx:316`) | 카탈로그 로드 실패 시 "검색 가능한 항목 목록을 불러오지 못했어요" / 지역 데이터 로드 실패 시 "결과를 불러오지 못했어요. 잠시 후 다시 시도해 주세요." (이미 구현됨, `App.tsx:70,114`) |

## 제외 판단

- **위치 확인/보정 UI**: 별도 화면 대신 메인 화면의 지역 선택 섹션에 "현재 위치 기준으로
  {구}로 자동 설정했어요" 안내문 + 기존 드롭다운으로 수정 가능하게 처리. 화면 분리 불필요.
- **병원/보건소 필터**: 메인 화면 결과 목록 위에 토글 버튼만 추가하면 되는 수준이라
  별도 화면 불필요.
